# 전달 전 검증 범위

이 문서는 **코드가 있다는 것**과 **전체 자료로 실제 재실행을 마쳤다는 것**을 구분하기 위한 기록이다.

## 확인 완료

- 비공개 GitHub 저장소와 Release 업로드를 완료했다. 별도 폴더에 **새로 clone하고 Release에서 실제 다운로드**하여 코드·데이터·모델·체크포인트 **156개 파일의 SHA-256**을 대조했다. 로컬 원자료를 연결해 대신 검사한 것이 아니다.
- `requirements.txt`와 `requirements-botsim.txt`로 각각 새 Python 환경을 설치했다. 기존 개인 가상환경에만 있던 라이브러리에 의존하지 않는지 확인했다.
- 새 다운로드·새 환경에서 동질성 검정, BotSim 판별기 **재학습**, OpenRouter 판별기 적용, fox8 외부 평가를 재실행했다. AUC·혼동행렬·동질성 비율의 기준 수치 대조를 통과했다. 작은 부동소수점 차이에는 절대 `1e-10`, 상대 `1e-9` 허용오차를 사용했다.
- BotSim 원문에서 적격 계정 선별을 전체 재실행했다. 기존 `01_적격계정.json`의 모든 JSON 값과 일치했다.
- 동봉 UD 캐시에서 기능어 목록을 다시 만들었다. 기존 목록 JSON의 모든 값과 일치했다.
- BotSim 봇 1계정·사람 1계정의 글 총 39개를 다시 파싱했다. 모든 원카운트가 기존 값과 일치했다.
- fox8 3계정의 전체 글을 다시 파싱했다. 저장된 해당 계정의 측정값과 모두 일치했다.
- fox8 원본 NDJSON.gz의 2,280개 계정 행에서 2,279개 고유 계정·368,028개 글을 읽어 제공 SQLite의 모든 열을 입력 순서대로 대조했다.
- FMR 통제 단위 테스트를 실행했다.
- 전체 댓글·politics 제한 코퍼스를 원문에서 다시 구성하고, 제공된 파싱 원카운트로 세 FMR 통제를 다시 계산했다. F·M·R 비교, 분량·게시판 통제, 목록 민감도까지 8개 결과 JSON에서 설정 메타데이터를 제외한 모든 결과 필드가 정확히 일치했다.
- GitHub에서 내려받은 fox8 압축 원자료로 SQLite를 새로 만들고, 모든 사용자·글 필드를 원자료와 다시 대조했다.
- 동질성 귀무 오류율 모의를 1,000회 다시 실행했다. 설정·소요시간을 제외하고 경로 문자열의 유니코드 표기를 통일하여 비교했을 때, 반복별 수치·요약·판정이 기존 결과와 정확히 일치했다.
- OpenRouter 저장 기록에서 55,590개의 종료 슬롯 행을 API 호출 없이 읽기 쉬운 데이터로 추출했다.
- 비밀 키 형태의 문자열과 코드의 인증정보 리터럴을 점검했다. 개인 계정 자격증명을 배포 자료에 넣지 않았다.

## 아직 완료라고 주장하지 않는 것

- BotSim·fox8 **전체 원문 재파싱을 포함한** `raw` 명령의 처음부터 끝까지 연속 실행. 실행 경로와 필요한 자료는 제공했지만, 위 표본 파싱 검증을 전량 재파싱 완료라고 부르지 않는다.
- 다른 운영체제·CPU에서의 비트 단위 동일성. 원 코드의 수치 관문과 `check_results.py`로 차이를 확인하도록 했다.
- OpenRouter API 재생성. 사용자의 요청대로 수행·제공 범위에서 제외했다.
- OpenRouter 표 a(`12-2_표a.py`)의 전체 재표집·민감도 재실행. 일부 계산 뒤 전달 범위를 정리하며 수동 중단했다. 기존 코드·결과는 포함했고 선택 실행 명령을 제공한다. 이를 재실행 완료로 세지 않는다. 저장된 OpenRouter 자료에 최종 판별기를 적용하는 `12-3`은 별도로 끝까지 검증했다.

## 재현 환경

- 이번 점검: macOS arm64, Python 3.13.7.
- 원 BotSim 파싱: Stanza 1.14.0 / Torch 2.11.0.
- 후기 fox8·판별기: Stanza 1.14.0 / Torch 2.10.0 / NumPy 2.4.3 / SciPy 1.17.1 / scikit-learn 1.8.0.
- macOS의 Rosetta/x86 Python과 arm64 NumPy를 섞으면 import 오류가 난다. Apple Silicon에서는 arm64 Python으로 환경을 만든다.
- 파싱 모델은 압축 자료에 동봉한 파일을 사용하고, 실행기의 환경 변수로 그 위치를 지정한다.

검증 기록은 [validation 폴더](../validation/)에 있다. 실행 시간이 포함된 원 로그는 각 작업폴더의 `logs/`에 쌓인다.
