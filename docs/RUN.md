# 실행 안내

## 처음 준비하기

검증 환경은 macOS Apple Silicon, Python 3.13.7이다. 다른 운영체제에서는 같은 패키지 버전의 설치 가능 여부와 마지막 대조 결과를 확인한다.

Homebrew가 설치되어 있다면:

```bash
brew install uv gh
gh auth login
gh repo clone ASEODA/bot-classification-repro
cd bot-classification-repro
bash run.sh
```

`gh`는 저장소 초대를 수락한 GitHub 계정으로 로그인한다. ZIP으로 받은 경우에도 비공개 데이터 다운로드를 위해 인증이 필요하다.

## 두 실행 방식

| 명령 | 시작점 | 다시 계산하는 범위 |
|---|---|---|
| `bash run.sh` | 제공된 계정별 파싱 카운트 | 사용률·문체 비교·세 통제·목록 민감도·귀무 모의·동질성·판별기 학습·외부 평가 |
| `bash run.sh full` | BotSim 원문, fox8 NDJSON.gz, UD | 적격 계정·목록 생성·전량 파싱·제한 코퍼스 측정부터 위 분석 전체 |

두 방식 모두 OpenRouter는 **저장된 생성 댓글과 고정 측정 자료**를 사용한다. OpenRouter API로 다시 생성하거나 해당 실험의 생성·파싱 과정을 다시 실행하지 않는다.

전체 실행에서는 측정 캐시 압축파일을 풀지 않는다. BotSim·fox8 측정값을 배포본에서 복사해 놓고 계산한 것처럼 처리하지 않는다. fox8의 SQLite는 원본 압축 데이터에서 만든다.

첫 실행에서 `.venv`를 만들고 고정 패키지를 설치한다. 전량 실행의 BotSim 파싱은 당시 버전에 맞춘 `.venv-botsim`을 별도로 사용한다. Stanza 모델도 동봉본을 사용한다. 원문의 정제 순서·계정별 문서 상한·정규화·수치 계산 규칙은 최종 연구와 같다.

## 결과 위치

- 빠른 분석: `work/`
- 원문부터 분석: `work-full/`
- 실제 결과 JSON·CSV: 작업폴더의 `research/단계별 진행경과/`
- 단계별 로그: 작업폴더의 `logs/`
- 검증: 작업폴더의 `validation/`

`result-comparison.json`과 `artifact-comparison.json`의 `passed`가 모두 `true`인지 확인한다. 후자는 48개 항목에서 계정별 카운트, 자질별 통계, 모든 계정 점수, fold 배정 및 모델 계수를 대조한다. 실수는 소수 10자리로 정규화하며 실행 시각·머신 경로는 비교하지 않는다.

## 중단 후 재개

같은 명령을 다시 실행한다.

```bash
bash run.sh full
```

이미 완료한 단계는 `validation/completed.json`의 코드·산출물 해시를 확인하고 건너뛴다. 진행 중이던 파싱은 파서의 중간 저장 지점에서 이어진다. 완료한 코드나 산출물을 직접 수정했다면 자동으로 섞어 실행하지 않고 중단한다. 이때는 새 폴더에 다시 내려받아 실행한다.

`prepare` 도중 다운로드·무결성 검사에서 실패한 경우, 불완전한 작업폴더를 다른 이름으로 옮긴 다음 다시 실행한다. 기존 결과는 지우지 않는다.

새 버전의 코드를 받은 뒤에는 예전 버전의 `work/`와 혼합하지 않는다. 원래 연구 폴더를 아카이브할 때도 **다운로드본의 검증 완료를 확인한 뒤** 이동한다.
