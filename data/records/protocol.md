# 평가 프로토콜

2026-10-01에 고정한 fox8 평가 명세를 이 배포본의 파일 구성에 맞추어 정리한 문서다. 원문을 그대로 옮긴 기록이 아니라 연구 방법을 편집한 설명이며, 원본 문서의 체크섬은 `provenance.json`에 있다.

## 1. 연구 설계와 평가 이력

평가 질문은 다음 두 가지다.

1. BotSim 학습 백분위 공간의 최근접 이웃 거리는 로지스틱 분류기에 추가적인 판별 정보를 제공하는가?
2. 그 추가 신호는 집단 간 중심 차이를 제거해도 유지되고, 퍼짐 차이를 줄이면 감소하는가?

방법 개발에는 fox8 개발 집합 995개 계정의 28개 설정, 486개 보조 결과, 중심·퍼짐 진단을 사용했다. 그보다 앞선 통합 분석은 이후 확인 집합에 배정된 계정을 포함한 적격 계정 1,991개 전체를 사용했다. 평가 명세를 정할 당시에는 학습 척도 이웃 점수와 합성 변환의 확인 집합 단독 결과를 살펴보지 않았다. 다만 확인 집합은 이전 분석에 전혀 사용되지 않은 독립 시험 집합은 아니다.

사전에 정한 탐색 순위에서는 군집 수 4의 Ward 군집 점수가 선택되었다. 최종 명세는 그 대신 k-최근접 이웃 거리를 사용했다. 이는 해당 순위 규칙의 선택 결과가 아니라 규칙에서 벗어난 선택이다.

로지스틱 가중치, 변환, 주 분석의 이웃 수, 결합 가중치는 평가 전에 고정한다. 확인 라벨은 AUC 계산, 부트스트랩 집단 구분, 집단별 합성 변환, 층화 하위표집에 사용하지만 L의 학습이나 G의 계산에는 사용하지 않는다.

## 2. 입력

- 확인 계정: `split_fox8.json`의 `확인` 필드. 봇 547개와 사람 449개, 총 996개다.
- 사람 자료원: botometer-feedback 116개, gilani-17 87개, midterm-2018 137개, varol-icwsm 109개다.
- 특성표: `../features/fox8.csv.gz`, 절단문 민감도 분석용 `../features/fox8_trunc.csv.gz`.
- 잔존 문구 제외 목록: `excluded_fox8.json`. 전체 표본 686개이며, 이 중 확인 집합 계정은 348개다.
- 분류기: `../../code/train.py`로 학습한 BotSim 모델. 학습에 fox8 라벨을 사용하지 않는다.

배포 입력의 체크섬은 `../manifest.json`에 있다. 개발·확인 계정 목록은 서로 겹치지 않으며 합치면 fox8 적격 표본 전체가 된다.

## 3. 점수 정의

P는 BotSim 학습 데이터에서 적합한 백분위 함수로 변환한 250개 특성이다.

- **L:** BotSim 로지스틱 분류기의 봇 확률.
- **G (k = 10):** 평가 집합 안에서 열 번째로 가까운 다른 계정까지의 L1 거리를 250으로 나눈 뒤 음수를 취한 값. 자기 자신은 제외하며 라벨은 사용하지 않는다.
- **S:** 집합 내 L과 G의 순위를 [0, 1]로 정규화한 뒤 같은 가중치로 평균한 값.

구현은 평가 집합 자체의 척도를 사용한 이웃 점수(`G_eval`)와 그 결합(`S_eval`)도 보고한다. 원래 명세에 기술적 비교로 포함된 k = 5, k = 20, 군집 수 4의 k-means는 이 배포본에서 실행하지 않는다.

## 4. 합성 변환

원 특성값을 변환한 뒤 동일하게 고정된 학습 백분위 변환을 적용한다. 집단 중심은 결측값을 제외한 특성별 중앙값이다.

| 조건 | 변환 |
|---|---|
| **W0: 관측값** | 변환하지 않은 특성 |
| **W1: 중심 차이 제거** | 각 봇 벡터를 사람 중앙값과 해당 봇의 봇 중앙값 대비 잔차의 합으로 대체. 사람은 유지 |
| **W2: 퍼짐 차이 축소** | 각 사람 벡터를 사람 중앙값과 무작위로 뽑은 봇 잔차의 합으로 대체. 봇은 유지 |
| **W3: 봇 측 잔차 대체** | 각 봇 벡터를 봇 중앙값과 무작위로 뽑은 사람 잔차의 합으로 대체. 기술적 비교만 수행 |

W1은 결정적 변환이다. W2는 `np.random.default_rng([20260101, 17, set_id, 2])`, W3는 `[20260101, 17, set_id, 1]`을 사용한다. W2의 추가 추출 4회는 시드 벡터 뒤에 e = 1, 2, 3, 4를 붙인다. 추가 추출은 잔차 표집에 대한 민감도를 보여주며, 기준 판정에는 주 추출을 사용한다.

## 5. 조작 확인

조작 확인 기준을 충족하지 못하면 해당 해석을 유보한다. 수치 결과는 그대로 보고한다.

| 항목 | 기준 | 개발 집합 참고값 |
|---|---|---|
| **M1, W2** | P에서 특성별 표준편차 중앙값의 봇·사람 절대 차이 ≤ 0.010, 집단 내 열 번째 이웃 거리 중앙값의 절대 차이 ≤ 0.010 | 0.003; 0.003 |
| **M2, W1** | 봇의 특성별 표준편차 중앙값이 W0 대비 변한 정도 ≤ 0.015, L AUC ≤ 0.60 | 0.006; 0.420 |
| **M3, W3** | 봇 측 잔차 대체로 줄어든 원래 퍼짐 격차의 비율. 기술적 비교만 수행 | 표준편차 52%; 이웃 거리 38% |

`code/evaluation.py`는 명세의 직접 판정(`느슨`)과 더 엄격한 판정(`엄격`)을 함께 보고한다. 엄격한 판정은 소수 셋째 자리 반올림 전후에 기준을 모두 충족해야 하며, M2에서는 L AUC의 신뢰구간 상한도 0.60 이하여야 한다.

## 6. 평가 부분집합과 부트스트랩

| 식별자 | 부분집합 | 봇 수; 사람 수 |
|---|---|---|
| 501 | 확인 집합 전체 | 547; 449 |
| A | 목표 봇 비중 50%, 25%, 10%, 5%. 수준별 3회 추출 | 449 / 150 / 50 / 24; 449 |
| 511–514 | 봇 전체와 사람 자료원 하나. 자료원 이름의 사전순 | 547; 116 / 87 / 137 / 109 |
| 521–524 | 봇 전체와 사람 자료원 하나를 제외한 나머지. 같은 순서 | 547; 333 / 362 / 312 / 340 |
| 531 | 절단문 민감도 특성표 | 547; 449 |
| 541 | 잔존 문구 목록에 포함된 확인 계정 348개 제외 | 제외 목록에 따라 결정 |

A의 봇 수는 비중 p를 사용한 `round(449 * p / (1 - p))`다. 정렬한 확인 봇 ID에서 비복원 추출하며 시드는 `[20260101, 17, 2, 100*p, s]`, s = 0, 1, 2다.

AUC와 대응 점수 차이에는 집단별 부트스트랩 2,000회와 백분위 95% 구간을 사용한다. 사람·봇의 부트스트랩 키는 각각 `(17, set_id, 1)`, `(17, set_id, 2)`다. A에서는 `(17, 600 + 100*p, s, 1)`, `(17, 600 + 100*p, s, 2)`를 사용한다. `common.boot_counts`는 각 키 앞에 20260926을 붙인다. 집단 안에 추가 층은 두지 않는다.

점수와 이웃 구조는 부분집합별로 한 번 계산하고 부트스트랩 반복 중에는 고정한다. 따라서 구간은 해당 부분집합과 점수 구성에 조건부인 불확실성을 나타낸다.

## 7. 판정 기준

임곗값은 개발 집합을 바탕으로 정했다. 아래 개발 집합 수치는 참고값이지 확인 근거가 아니다.

| 기준 | 정의 | 개발 집합 참고값 |
|---|---|---|
| **P17-a** | 501에서 S − L의 95% 구간 하한 > 0 | +0.049 [0.036, 0.063] |
| **P17-b** | 501/W1에서 G AUC의 95% 구간 하한 ≥ 0.90 | 0.989 [0.983, 0.994]; L 0.420 |
| **P17-c** | 501/W2에서 G AUC의 95% 구간 상한 ≤ 0.75, 점추정 차이 G AUC(W0) − G AUC(W2) ≥ 0.20 | 0.598 [0.564, 0.633]; 차이 0.387; 추가 추출 0.487–0.570 |
| **P17-d** | 수준별 3회 평균을 사용하여, 봇 비중 10%·5%의 평균 S − L에서 50%의 평균 S − L을 뺀 값 ≤ +0.005 | −0.015 |
| **P17-e** | 50%·25%의 6회 모두 S − L의 구간 하한이 양수이며, 5%에서는 3회 중 최대 2회가 양수 | 6/6; 1/3 |
| **P17-f** | 자료원 하나씩 제외한 4개 부분집합 모두, 단일 자료원 부분집합 최소 3개에서 S − L의 구간 하한이 양수 | 4/4, 최솟값 +0.030; 4/4, 최솟값 +0.011 |
| **P17-g** | 531과 541 각각에서 S − L의 구간 하한이 양수이고 P17-b·P17-c 충족 | 531: +0.049, W1 0.990, W2 0.563; 541: +0.045, W1 0.980, W2 0.403 |
| **P17-h** | 501에서 S − S_eval의 점추정값 > 0. 기술적 비교만 수행 | +0.013 [0.007, 0.019] |

## 8. 해석과 산출물

P17-a는 추가 판별력의 근거다. P17-b·P17-c·M1·M2까지 충족하면 합성 분석은 추가 신호가 중심만이 아니라 집단 내 퍼짐과 관련됨을 뒷받침한다. 조건을 충족하지 못하면 그에 맞추어 해석을 제한한다. P17-d부터 P17-g는 표본 구성과 원문 제외에 대한 민감도를 나타내며, 충족하지 못한 기준도 결과에 포함한다.

이 분석은 퍼짐의 가능한 원인인 모델 생성, 공통 운영자, 시기, 주제를 구별하지 못한다. 개발 집합의 결과는 명세 설정에 사용한 것으로 독립적인 확인 근거가 아니다.

`../../code/evaluation.py`는 부분집합 점수, 부트스트랩 구간, 합성 조건 결과, 조작 확인 결과를 `results/evaluation.json`에 기록한다. `../../code/run.py`는 `results/summary.md`를 생성하고 계산 결과를 `expected/`와 대조한다.
